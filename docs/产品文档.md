## 一、产品概述

### 1.1 产品简介

「黑马记账」是一款**个人记账桌面应用**，运行在 Windows 和 macOS 电脑上。

- 记录每一笔**支出**和**收入**（人民币 ¥）
- 支出/收入按**二级分类**管理（一级大类 → 二级小类），分类已内置，无需自己创建
- 提供**统计报表**：看钱花在哪、每月收支趋势
- 支持**导出 Excel/CSV** 和**数据备份/恢复**

### 1.2 设计哲学

> **打开即记、三秒完成一笔、数据永远在自己手里。**

### 1.3 目标用户

- 不懂技术的记账初学者：讨厌复杂操作，只想要"记下来、看得懂"
- 关注隐私的用户：账单数据完全存在自己电脑里，不联网、不上传、无需注册账号
- 想从手机记账迁移到电脑端的用户

### 1.4 基本参数

| 项目 | 说明 |
|---|---|
| 运行平台 | Windows 10/11、macOS |
| 界面语言 | 中文 |
| 货币 | 人民币 ¥ |
| 数据存储 | 全部保存在本机（SQLite 数据库文件），无需联网、无账号 |
| 首次发布版本 | v1.0 |

## 二、功能需求

### 2.1 记一笔（核心功能）

| 功能点 | 说明 |
|---|---|
| 快速记账 | 选「支出/收入」→ 输入金额 → 选分类（两级联动）→ 保存 |
| 金额输入 | 大号数字键盘（0-9、小数点、退格），也支持电脑键盘直接输入；金额精确到分 |
| 日期 | 默认今天，可修改（日期选择器） |
| 备注 | 可选填（如"地铁到公司"） |
| 最近使用分类置顶 | 常用小类排前面，减少点击 |
| 连续记账 | 保存成功后清空金额，方便连续记下一笔 |

### 2.2 账本列表（流水查看与管理）

| 功能点 | 说明 |
|---|---|
| 按日分组 | 按月份翻页，每天一组，组内按时间倒序 |
| 月度汇总条 | 当月支出合计、收入合计、结余 |
| 编辑/删除 | 点击任意一笔可修改金额、分类、日期、备注；删除需二次确认 |
| 空状态引导 | 当月无记录时显示"还没有记录，点右下角按钮记一笔吧" |

### 2.3 统计报表

| 功能点 | 说明 |
|---|---|
| 今日汇总 | 今日支出、今日收入、今日结余 |
| 本月汇总 | 本月支出、收入、结余、支出笔数 |
| 分类占比图 | 环形图：本月各类支出/收入的金额占比，可切换支出/收入 |
| 月度趋势图 | 折线图：近 12 个月收支趋势，可切换支出/收入 |

### 2.4 数据管理

|---|---|
| 导出 Excel | 全部流水导出为 .xlsx 文件（可用 Excel/WPS 打开） |

## 四、页面设计

### 4.1 首页

- 顶部：今日日期 + 问候语（如"今天，8月29日"）
- 今日卡片：今日支出（大字号）、今日收入、今日结余（负数显示红色）
- 本月卡片：本月支出、本月收入
- 最近 5 笔流水（仅展示，点"查看全部"跳转账本页）
- 底部通栏大按钮「记一笔」—— 全应用最高频操作，任何页面都能一眼看到

### 4.2 记一笔页

- 顶部切换：支出（默认）/ 收入
- 金额输入：大号数字显示 + 九宫格数字键盘
- 分类选择：左侧一列一级大类（带图标），右侧一列二级小类；最近使用的 4 个小类置顶
- 日期与备注：日期默认今天可改；备注一行输入框（选填）
- 保存成功提示"已记一笔"，自动清空金额，方便连续记账

### 4.3 账本页

- 顶部月份切换（◀ 2026年8月 ▶）
- 当月汇总条：支出合计 / 收入合计 / 结余
- 流水列表：按日期分组，每天显示"支出 ￥xx / 收入 ￥xx"小计；每笔显示：分类图标 + 小类名 + 备注 + 金额
- 点击任意一笔 → 弹出编辑抽屉：可改金额、分类、日期、备注；可删除（二次确认）
- 约定：支出金额为深色、收入金额为绿色，一眼区分

### 4.4 统计页

- 顶部汇总卡片：今日支出/收入、本月支出/收入/结余
- 分类占比环形图：默认"本月 · 支出"，可切换收入；图例显示各分类金额与百分比
- 月度趋势折线图：近 12 个月，可只看支出/只看收入
- 所有图表基于当前数据实时计算

### 4.5 设置页

- 「导出 Excel」「导出 CSV」按钮：弹出系统保存对话框，选位置保存
- 「创建备份」：生成 .hbak 文件
- 「从备份恢复」：选择 .hbak 文件 → 红色警示确认框 → 恢复
- 关于：应用名称、版本、数据存储说明（"数据保存在你的电脑上，不会上传任何服务器"）

## 六、技术方案附录

> 本附录面向开发，由 Claude Code 实施。用户可跳过本附录，或感兴趣时阅读。

### 6.1 整体架构

```
┌─────────────────────────────────────────────────┐
│              Electron 应用                       │
│  ┌───────────────────────────────────────────┐  │
│  │ 渲染进程（Renderer）— Vue 3 界面           │  │
│  │ Vue Router / Pinia / element-plus / ECharts│  │
│  └──────────────────┬────────────────────────┘  │
│                     │ contextBridge 白名单 API   │
│  ┌──────────────────▼────────────────────────┐  │
│  │ 预加载脚本（Preload）                     │  │
│  └──────────────────┬────────────────────────┘  │
│                     │ IPC（进程间通信）           │
│  ┌──────────────────▼────────────────────────┐  │
│  │ 主进程（Main）— Node.js                   │  │
│  │ 窗口管理 / SQLite(better-sqlite3) /      │  │
│  │ 文件读写（导出、备份、恢复）              │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

**关键决策**：
- SQLite 操作全部放在主进程：避免渲染进程开 Node 权限带来的安全风险
- 渲染进程只通过 preload 暴露的白名单 API 访问数据（`window.api.xxx`）
- 安全基线固定：`contextIsolation: true`、`nodeIntegration: false`
- **金额以"分"为单位整数存储**（界面显示时 ÷100），彻底杜绝 0.1+0.2≠0.3 这类浮点误差

### 6.2 数据库设计

三张业务表 + 一张版本表：

```sql
-- 大类表（一级分类）
CREATE TABLE IF NOT EXISTS categories (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  type        TEXT    NOT NULL CHECK (type IN ('expense', 'income')),
  name        TEXT    NOT NULL,
  icon        TEXT    DEFAULT '',
  sort_order  INTEGER NOT NULL DEFAULT 0,
  is_default  INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);

-- 小类表（二级分类）
CREATE TABLE IF NOT EXISTS sub_categories (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
  name        TEXT    NOT NULL,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  is_default  INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);

-- 流水表（记账记录）
CREATE TABLE IF NOT EXISTS transactions (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  type        TEXT    NOT NULL CHECK (type IN ('expense', 'income')),
  amount      INTEGER NOT NULL,              -- 金额，单位：分
  category_id INTEGER,                       -- 指向 sub_categories.id
  date        TEXT    NOT NULL,              -- YYYY-MM-DD
  note        TEXT    DEFAULT '',
  created_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime')),
  updated_at  TEXT    NOT NULL DEFAULT (datetime('now', 'localtime')),
  FOREIGN KEY (category_id) REFERENCES sub_categories(id) ON DELETE SET NULL
);

CREATE INDEX idx_transactions_date      ON transactions(date);
CREATE INDEX idx_transactions_type_date ON transactions(type, date);
CREATE INDEX idx_transactions_category  ON transactions(category_id);

-- 表结构版本管理（数据库迁移用）
CREATE TABLE IF NOT EXISTS schema_version (
  version    INTEGER NOT NULL,
  applied_at TEXT    NOT NULL DEFAULT (datetime('now', 'localtime'))
);
```

- 数据库文件位置：`app.getPath('userData')/heimabook.db`
  - Windows：`%APPDATA%\黑马记账\heimabook.db`
  - macOS：`~/Library/Application Support/黑马记账/heimabook.db`
- 首次启动：建表 → 检查分类表为空 → 写入全部预设分类（种子数据）

### 6.4 技术选型（阶段 2 开工前逐项请用户确认）

| 决策点 | 候选方案 | 对比要点 | 推荐 |
|---|---|---|---|
| 桌面框架 | Electron vs Tauri | Electron 成熟稳定、生态全、体积大（约90MB）；Tauri 体积小省内存但 Rust 门槛高 | **Electron**（已确认） |
| 构建工具 | electron-vite vs 其他 | electron-vite 主/预加载/渲染三端统一配置、热更新、模板成熟 | **electron-vite** |
| UI 组件库 | element-plus vs naive-ui | element-plus 中文文档最全、组件最齐、社区答案多，求稳首选 | **element-plus** |
| 图表库 | ECharts vs Chart.js | ECharts 环形图/折线图强、中文文档好（按需引入约300KB） | **ECharts** |
| 状态管理 | Pinia vs Vuex | Pinia 是 Vue 官方当前推荐、写法简洁 | **Pinia** |
| SQLite 驱动 | better-sqlite3 vs 其他 | 同步 API 简单可靠、Electron 生态最成熟 | **better-sqlite3** |
| 打包工具 | electron-builder vs 其他 | 双平台（NSIS/dmg）配置成熟、一键出安装包 | **electron-builder** |
| Excel 导出 | xlsx vs exceljs | xlsx 轻量、API 简单、CSV/Excel 都能写 | **xlsx（社区版）** |
